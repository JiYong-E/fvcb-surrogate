# fvcb-surrogate

Reproduction code for Lee & Yun, *FvCB-Augmented Machine Learning Surrogate for Coupled C3
Leaf Gas Exchange*.

Repository: https://github.com/JiYong-E/fvcb-surrogate

Data, trained models and evaluation tables are deposited on Zenodo,
**doi:10.5281/zenodo.22686734** (CC-BY-4.0). The external Scots pine field record is not
redistributed by either archive — it is the SMEAR II shoot-chamber dataset of Aalto (2023),
Zenodo **doi:10.5281/zenodo.10360968**; `05_field_validation/` processes its raw
`FFluxYYYY.NNN` files.

## Layout

| Dir | Stage | Language | Entry point |
|---|---|---|---|
| `01_design/` | nested-LHS training designs + independent validation/test designs | Julia | `julia 01_nested_lhs.jl`, `julia 02_independent_eval_lhs.jl` |
| `02_features/` | run every design row through the reference solver (`*_sim` columns), then append the 3 FvCB pre-solver features (`Ac_init`, `Aj_init`, `Ap_init`) | Julia | `01_simulate_reference.jl` → `02_fvcb_features.jl` |
| `03_training/` | CatBoost training of M_base / M_aug / M_full at 5 sizes x 5 reps, scored on the seed-1225 test design | Julia | `julia --project=. 01_train.jl Maug ./data ./out/Maug 01 02 03 04 05` (then `Mbase`, `Mfull`) → `02_evaluate.jl` |
| `04_onnx/` | four `.cbm` per model → one fused four-output ONNX graph | Python | `01_fuse_onnx.py` |
| `05_field_validation/` | Scots pine: build inputs, calibrate V_cmax25/J_max25 (R_d25 fixed), run reference + surrogate, summarize | Python + Julia | `01_prepare_pine.py` → `02_fit_reference.jl` → `03_run_surrogate.py` → `03_run_surrogate.py --summarize` (or all at once: `04_run_all.py`) |
| `06_benchmark/` | fused-ONNX vs reference-solver speed/size (Table 6, Figure 6) | Julia | `01_reference_timing.jl` → `02_benchmark.jl` |
| `07_field_forcing/` | AmeriFlux US-Ton: build sequential forcing, run reference + surrogate, hot-drought thresholds and seasonal summary (§2.6/§3.3, Figure 4c,d) | Python + Julia | `01_prepare_forcing.py` → `02_run_reference.jl` → `03_run_surrogate.py` → `05_summarize.py`; separately `00_build_nmae_table.py` → `04_thresholds.py` |
| `reference_solver/` | pointer to LeafGasExchange.jl | — | — |

## Reproduce

1. `01_design/` — regenerate the rep01–05 training designs + the validation (seed 424242) and
   test (seed 1225) designs. Seeds and sampled parameter ranges match `seeds.csv` /
   `parameter_ranges.csv` (documentation copies of the constants hardcoded in `01_nested_lhs.jl`;
   not read by the code).
2. `02_features/01_simulate_reference.jl` — run every design row through LeafGasExchange.jl
   `ModelC3BB` to produce the `*_sim` columns; then `02_features/02_fvcb_features.jl` appends
   the three FvCB pre-solver features and `VPD`.
3. `03_training/` — `julia --project=. 01_train.jl Maug`, then `Mbase`, `Mfull`; then `02_evaluate.jl`.
4. `04_onnx/01_fuse_onnx.py` — build the fused ONNX graphs.
5. `06_benchmark/01_reference_timing.jl` — time the reference solver on the fixed 100-row
   sample; then `06_benchmark/02_benchmark.jl` — fused-ONNX vs that reference timing.
6. `05_field_validation/04_run_all.py` — Scots pine, starting from the Aalto (2023) FFlux archive.
7. `07_field_forcing/` — AmeriFlux US-Ton. Two independent chains.
   The forcing chain starts from the FLUXNET-1F download: `01_prepare_forcing.py` →
   `02_run_reference.jl` → `03_run_surrogate.py` → `05_summarize.py` (Figure 4d).
   The threshold chain needs no forcing run: `00_build_nmae_table.py` builds the per-row
   NMAE table over the final test design (this also underlies Figure 3), then
   `04_thresholds.py` applies the US-Ton p90 thresholds to it (Figure 4c). The deposit
   carries replicate 1 only, so `00_build_nmae_table.py` defaults to `FVCB_REPS=rep01`;
   its regime composition is exact either way, and the error columns are then a
   single-replicate version of the paper's five-replicate mean.

The rep01 10M training data (`*_sim` + features already appended), the rep01 trained models,
and the two eval designs are on Zenodo, so steps 1–3 can be skipped for replicate 1. The
other four replicates are regenerated by steps 1–2 with the seeds in `seeds.csv`.

### Reproducing from the Zenodo deposit only (no retraining)

Unzip the Zenodo deposit's `data.zip`, `models.zip` and `results.zip` (10.5281/zenodo.22686734)
next to each other. The deposit's `models/rep01/<size-label>/` layout (`1k`/`10k`/`100k`/`1m`/`10m`
instead of `n<N>`, no `stage2_metrics.csv`/`stage2_feature_map.csv` alongside the `.cbm` files)
is auto-detected by `04_onnx/fuse_core.py`, `03_training/02_evaluate.jl` and
`05_field_validation/03_run_surrogate.py` -- `best_iter` and the M_aug feature list are read
from `results/per_model_metrics.csv` and `STAGE1_FEATURES` respectively when the training-run
files aren't present. Since only replicate 1 is deposited, set `FVCB_REPS=rep01`.

```bash
# re-score the deposited models against the deposited final_test design
cd 03_training
FVCB_TEST_PATH=/path/to/data/final_test FVCB_MODELS_ROOT=/path/to/models FVCB_REPS=rep01 \
  julia --project=. 02_evaluate.jl

# rebuild the fused ONNX graphs (rep01, all 5 sizes) from the deposited .cbm models
cd ../04_onnx
FVCB_MODELS_ROOT=/path/to/models python 01_fuse_onnx.py

# Scots pine field validation, Zenodo-only
cd ../05_field_validation
FVCB_MODELS_ROOT=/path/to/models FVCB_REPS=rep01 python 04_run_all.py
```

## Environments

- **Julia** — every Julia-using directory (`01_design/`, `02_features/`, `03_training/`,
  `05_field_validation/`, `06_benchmark/`) has its own pinned `Project.toml` + `Manifest.toml`.
  `02_features/`, `05_field_validation/` and `06_benchmark/` all pin the same LeafGasExchange.jl
  and Cropbox commits used for the reference solver (`reference_solver/`);
  `05_field_validation/` additionally pins **Optim** (for the V_cmax25/J_max25 calibration in
  `02_fit_reference.jl`), and `06_benchmark/` pins `BenchmarkTools`/`ONNXRunTime`. So
  `julia --project=.` from any of these five directories is self-contained -- no environment
  needs to be assembled by hand.
- **Python** — `requirements.txt`.

## Configuration (env vars)

| var | used by | default |
|---|---|---|
| `SMEARII_DIR` | `05_field_validation/` | `./smearii` — the Aalto (2023) FFlux files |
| `FVCB_MODELS_ROOT` | `04_onnx/`, `03_training/02_evaluate.jl`, `05_field_validation/03_run_surrogate.py` | `03_training/out/Maug` |
| `FVCB_TEST_PATH` | `03_training/02_evaluate.jl` | `03_training/../data/final_test` |
| `FVCB_REPS` | `03_training/02_evaluate.jl`, `05_field_validation/03_run_surrogate.py` | `rep01,rep02,rep03,rep04,rep05` -- set to `rep01` for Zenodo-only |
| `ONNX_DIR` | `06_benchmark/` | `./onnx` |
| `EVAL_PATH` | `06_benchmark/` | `./data/final_test/part-000001.parquet` |
| `JULIA` / `JULIA_PROJECT` | `05_field_validation/04_run_all.py` | `julia` / `.` (works out of the box now that `05_field_validation/Project.toml` exists) |

## Notes

- Scripts use repo-relative paths and the environment variables in the table above; set those
  for your layout rather than editing the scripts.
- `05_field_validation/02_fit_reference.jl` is the reference-solver calibration routine applied
  to the Scots pine records (`04_run_all.py` drives it).
